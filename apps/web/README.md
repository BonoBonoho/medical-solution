# @mediwork/web

관리자 웹. Next.js 15 App Router.

현재 구현된 화면은 **근무표 그리드** 하나다. 로드맵에서 기술적 최난도로 잡아둔
구간이라 먼저 만들었다.

## 실행

```bash
pnpm --filter @mediwork/api start        # :3000
pnpm --filter @mediwork/web dev          # :3001
```

`http://localhost:3001` 로 들어가면 시드 근무표로 리다이렉트된다.
API가 떠 있지 않으면 **샘플 근무표**로 넘어가고, 화면 상단에 그 사실과 사유를
표시한다. 편집과 규칙 평가는 샘플에서도 실제와 동일하게 동작한다(저장만 안 된다).

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | `http://localhost:3000` | 코어 API 주소 |
| `NEXT_PUBLIC_DEV_AUTH` | 시드 수간호사 dev 토큰 | 운영에서는 세션 JWT로 교체 |

API 쪽에서는 `CORS_ORIGINS`가 이 웹의 출처를 포함해야 한다(기본값이
`http://localhost:3001`이라 로컬에서는 그대로 동작한다).

## 근무표 그리드

### 왜 클라이언트에서 규칙을 다시 평가하는가

수간호사는 한 번에 30명 × 31칸을 채운다. 셀을 바꿀 때마다 서버에 물으면
900번을 기다려야 해서 아무도 쓰지 않는다.

그렇다고 웹이 규칙 판정을 따로 구현하면 **편집 중에는 초록불이었는데 확정하면
막히는** 상태가 생긴다. 사용자 입장에서 원인을 알 수 없는 최악의 버그다.

그래서 계산은 `@mediwork/domain`의 `evaluateRosterPlan()` 한 벌만 두고,
서버와 웹이 **같은 함수를 부른다.** API는 이 함수의 입력 일체(`plan`)를
응답에 실어 보내고, 웹은 편집할 때마다 그 입력을 갱신해 다시 부른다.
화면에 뜨는 위반과 확정 시 서버가 막는 위반이 정의상 일치한다.

```
API  ─ plan ─→  웹
 │               │
 └─ evaluateRosterPlan(plan) ─┘   같은 순수 함수
```

### 키보드

셀마다 드롭다운을 열게 하면 900번 클릭이 된다. 키보드만으로 끝까지 편집된다.

| 키 | 동작 |
|---|---|
| `←` `→` `↑` `↓` | 셀 이동 |
| `Home` / `End` | 행의 처음 / 끝 |
| `D` `E` `N` `O` `V` | 근무유형 입력 후 오른쪽 칸으로 이동 |
| `Backspace` / `Delete` | 배정 삭제 |

입력 후 자동으로 오른쪽으로 넘어가는 것은 "한 사람의 한 달을 쭉 채우는"
실제 작업 흐름에 맞춘 것이다.

### 위반 표시

- **색만으로 표시하지 않는다.** 색각 이상이 있는 사용자에게 색만 쓴 근무표는
  위반이 아예 보이지 않는 화면이 된다. 테두리 + 모서리 점 + `aria-label`을
  함께 쓴다.
- **주 단위 위반은 그 주 전체 칸에 칠한다.** 52시간 초과나 주휴일 부족은
  특정 하루의 문제가 아니라 그 주 전체의 문제이고, 한 칸만 칠하면 어느
  구간을 고쳐야 하는지 알 수 없다.
- 칸을 선택하면 그 칸에 걸린 위반만, 선택을 풀면 전체 위반을 보여준다.
  각 위반에는 **근거 조문**과 **해결 방법**이 함께 붙는다 — "규칙 위반"만
  뜨는 시스템은 아무도 쓰지 않는다.

## 테스트

```bash
pnpm --filter @mediwork/web test
```

`src/lib/grid.ts`(순수 로직)를 대상으로 한다. 위반이 어느 칸에 매핑되는지가
틀리면 화면에는 표시가 없는데 확정은 막히는 상태가 되므로, 렌더링과 분리해
직접 확인한다.

## 미구현

- 편집 결과 저장(`PATCH /rosters/:id/assignments`). 지금은 화면 안에서만 바뀐다.
- 되돌리기/다시하기. `withCellChanged`가 plan을 불변으로 다루므로 이력 스택만
  얹으면 된다.
- 가상 스크롤. 30명 × 31일까지는 필요 없지만 수백 명 규모에서는 필요하다.
  재평가 비용도 그 지점에서 `useDeferredValue`나 워커로 옮겨야 한다.
- 근무표 외 화면(근태 현황, 휴가, 승인 대기 처리) 전부.
