## 2. Phase 0 — 검증·준비 (6주)

**목표: 만들기 전에 틀린 가정을 걷어낸다.**

### 2.1 ⚖️ 법률 검토 (최우선, 병행 불가 항목 있음)

| 항목 | 담당 | 왜 지금인가 |
|---|---|---|
| **위치기반서비스사업 신고 대상 여부** | 개인정보 법무 | 신고 대상이면 절차에 시간이 걸리고, 설계 자체가 달라질 수 있음 |
| Claude API 국외 이전 해당 여부 | 개인정보 법무 | 해당 시 익명화 설계를 아키텍처에 반영해야 함 |
| 근기법 §59 특례 서면합의 요건 | 공인노무사 | 규칙 엔진 설계의 전제 |
| 전공의법 현행 수치 확정 | 공인노무사 | Phase 4 대상이나 데이터 모델에 영향 |
| PC 모니터링 도입 절차 | 공인노무사 | Phase 3 대상이나 원칙 확정 필요 |

**위치정보 신고 건은 Phase 0에서 결론이 나야 합니다.** MVP를 다 만들고 "신고 대상이었다"가 되면 출시가 밀립니다.

### 2.2 고객 검증

```
□ 파일럿 병원 3곳 확보 (다른 규모·유형)
   · 요양병원 1 (교대 근무 많음)
   · 전문병원 1 (중형)
   · 네트워크 의원 1 (다지점)
□ 각 병원의 실제 근무표 Excel 3개월치 수집 (익명화)
   → 골든 테스트 픽스처로 사용
□ 수간호사 밀착 관찰 1일 × 3곳
   → 듀티표 작성 과정 실측. 시간, 도구, 제약, 예외 상황
□ 현행 근태 관리 방식 조사
   → 지문인식기? Excel? 기존 SaaS? 마이그레이션 난이도 판단
```

**듀티표 작성 관찰이 이 단계에서 가장 가치 있습니다.** 제약 조건 목록을 상상으로 만들면 반드시 틀립니다.

### 2.3 기술 검증 (PoC)

| PoC | 검증 내용 | 실패 시 대응 |
|---|---|---|
| **CP-SAT 스케줄링** | 50명 × 30일, 실제 제약으로 60초 내 실행가능해 | 제약 완화 전략, 휴리스틱 초기해 |
| **모바일 WiFi 접근** | iOS/Android에서 BSSID 획득 가능 여부 실기기 확인 | GPS 중심 설계로 전환, 키오스크 비중 확대 |
| **근무표 그리드 성능** | 200명 × 31일 편집 반응 100ms 이내 | Canvas 렌더링, 가상 스크롤 |
| **자연어 제약 파싱 정확도** | 실제 수간호사 발화 50건 파싱 정확도 | 구조화 UI 병행 제공 |

**WiFi PoC를 반드시 실기기로** 합니다. [06 §2.2](06-mobile-attendance.md#22-플랫폼별-wifi-접근-제약)에서 다룬 대로 iOS와 Android의 제약이 다르고, 문서만으로는 정확히 알 수 없습니다.

- PoC 결과 보고서 및 아키텍처 확정

## 3. Phase 1 — MVP (5개월)

**목표: 병원 하나가 이 제품만으로 근태를 운영할 수 있다.**

### 3.1 스프린트 계획 (2주 단위)

| 스프린트 | 내용 |
|---|---|
| S1-S2 | 프로젝트 셋업, 인증, 테넌트/RLS, 조직·구성원, 권한 |
| S3-S4 | 근무유형 정의, 근무표 그리드 편집기 (기술적 최난도) |
| S5-S6 | 모바일 앱 기초, 출퇴근 기록 (GPS/WiFi), 위치 검증 |
| S7 | 오프라인 큐, 기기 바인딩, 무결성 검증 |
| S8-S9 | 규칙 엔진, 근로시간 집계, 52시간 경보 |
| S10 | 휴가 정책, 연차 자동 산정 |
| S11 | 결재 엔진 (범용), 휴가 신청·승인 |
| S12 | 근태 수정 요청, 야근 신청·승인 |
| S13 | 관리자 대시보드, 급여 Export |
| S14 | 파일럿 투입, 버그 수정, 데이터 마이그레이션 지원 |

### 3.2 위험 구간

**S3-S4 근무표 그리드**가 가장 위험합니다. 200명 × 31일 = 6,200셀을 드래그로 편집하면서 실시간 규칙 검증까지 하는 UI는 일반적인 React 방식으로는 감당이 안 됩니다.

```
대응
 ├─ S3 시작 전 스파이크 3일: 렌더링 방식 결정
 │   (DOM 가상화 vs Canvas vs 하이브리드)
 ├─ 규칙 검증은 웹워커에서 실행 (메인 스레드 블로킹 방지)
 └─ 최악의 경우 MVP는 100명 규모로 제한하고 Phase 2에서 최적화
```

**S8-S9 규칙 엔진**도 위험합니다. 근로시간 계산은 엣지케이스가 끝없이 나옵니다.

```
대응
 ├─ Phase 0에서 확보한 실제 데이터로 골든 테스트 먼저 작성
 ├─ 테스트 케이스 목록을 노무사와 함께 검토
 └─ 계산 로직은 packages/domain 순수 함수로 격리 (테스트 용이성)
```

### 3.3 MVP 완료 기준 (Definition of Done)

```
□ 파일럿 병원 1곳이 1개월간 이 시스템만으로 근태 운영
□ 급여 담당자가 Export 데이터로 급여 계산 완료
□ 근무표 작성이 시스템 내에서 완결 (Excel 병행 없음)
□ 출퇴근 기록 성공률 99% 이상
□ 위치 검증 실패로 인한 수동 승인 5% 이하
□ 골든 테스트 전부 통과
□ 테넌트 격리 테스트 통과
□ 취약점 진단 완료 및 High 이상 조치
```

**"Excel 병행 없음"이 진짜 기준입니다.** 사용자가 Excel을 계속 쓴다면 MVP는 실패입니다.

### 3.4 MVP에서 제외하는 것

의도적으로 뺍니다. 넣으면 5개월이 8개월이 됩니다.

| 제외 | 이유 |
|---|---|
| AI 근무표 생성 | 수동 편집이 안정된 후에 얹어야 함 |
| PC 사용 통제 | 법적 절차 준비가 별도로 필요 |
| 수가 리포트 | 고시 확인과 검증에 시간이 필요 |
| 전공의 관리 | 1차 타겟에 전공의가 거의 없음 |
| 당직/온콜 정밀 산정 | 정책 결정이 미완 ([02 §8](02-domain-rules.md#8-미해결-논점-구현-전-결정-필요)) |
| SSO, 외부 연동 | 중소 병원 수요 낮음 |

| 도입 설정 마법사 | 2주 | 도입 리드타임 단축 |

### 4.1 AI 듀티표 롤아웃 전략

한 번에 전면 공개하지 않습니다.

```
Week 1-4  : 파일럿 1개 병동에서 "제안만" (관리자가 참고용으로 봄)
            → 셀 수용률 측정. 60% 미만이면 제약 모델 재작업
Week 5-6  : 수용률 80% 도달 시 파일럿 병원 전 병동 확대
Week 7-8  : 전 고객 베타. 기존 근무표와 나란히 비교하는 UI 제공
정식      : 수용률 85% 안정 + 하드 제약 위반 0 유지 시
```

**하드 제약 위반이 1건이라도 나오면 롤아웃을 중단**합니다. 근무표에서 법정 휴식시간을 어기는 것은 신뢰 문제가 아니라 법 문제입니다.

| 기능 | 기간 | 비고 |
|---|---|---|
| **수가 리포트 (간호등급)** | 6주 | ⚖️ 고시 확인 + 병원 검증 필수 |
| **PC 사용 통제** | 6주 | 법적 절차 준비 병행 |
| HR 어시스턴트 (RAG) | 4주 | |
| 이상 근태 탐지 | 3주 | 규칙 기반 |
| 다지점 관리 | 3주 | 네트워크 의원 대응 |
| 데이터 마이그레이션 도구 | 2주 | |

### 5.1 수가 리포트 주의사항

돈과 직결되므로 신중하게 진행합니다.

```
1. 현행 고시 원문 확보 및 산정 로직 작성
2. 파일럿 병원의 과거 신고 자료와 대조 검증
   → 우리 계산 결과와 실제 신고값이 일치하는지
3. 불일치 원인 분석 (규칙 누락? 데이터 문제?)
4. 3개 이상 병원에서 검증 통과 후 출시
5. 출시 시 면책 문구와 검토 유도 UI 필수 ([05 §5](05-api-design.md#5-컴플라이언스-api))
```

**검증 없이 출시하면 안 됩니다.** 잘못된 신고는 환수로 이어지고, 그 책임 소재는 반드시 분쟁이 됩니다.

### 5.2 PC 통제 롤아웃

```
Week 1-4 : 개발
Week 5-6 : 사내 도그푸딩 (우리 팀에 먼저 적용)
Week 7-8 : 파일럿 병원 1곳, LOG_ONLY 모드 2주
Week 9+  : 차단 모드 전환, 이의제기 건수 모니터링
```

**사내 도그푸딩이 중요합니다.** 우리 팀이 쓰기 싫은 기능을 고객에게 팔면 안 됩니다.

### 8.1 리스크 1이 가장 시급합니다

## 9. 마일스톤과 판단 지점

각 단계 끝에 **계속할지 판단하는 지점**을 둡니다.

| 시점 | 판단 기준 | 미달 시 |
|---|---|---|
| Phase 0 종료 | 법률 리스크 해소 + PoC 전부 통과 + 파일럿 3곳 확보 | 설계 재검토 또는 범위 축소 |
| MVP 종료 | 파일럿 1곳 Excel 병행 없이 1개월 운영 | 원인 분석 후 MVP 연장 (다음 단계 진입 금지) |
| Phase 2 종료 | AI 수용률 85% + 유료 전환 병원 5곳 | AI 포지션 조정 (완전자동 → 작성 보조) |
| Phase 3 종료 | 유료 20곳 + 월 이탈 2% 이하 | 세그먼트 재검토 |

**MVP 종료 판단이 가장 중요합니다.** 파일럿이 Excel을 계속 쓰는데 Phase 2로 넘어가면, AI 근무표를 만들어도 쓰지 않습니다.
