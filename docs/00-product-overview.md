# 00. 제품 개요

## 1. 문제 정의

### 1.1 병원 관리자가 실제로 겪는 문제

**A. 근무표(듀티표) 작성이 수작업**
- 병동 수간호사가 매월 Excel로 3교대 근무표를 작성. 병동당 **2~5일** 소요.
- 고려해야 할 제약: 개인 희망휴무(오프 신청), 나이트 연속 제한, D→N 금지 패턴, 연차 소진, 신규 간호사 프리셉터 페어링, 병동별 최소 인력, 야간전담 인원 수, 파트타임 근무자.
- 작성 후에도 개인 사정(질병, 경조사)으로 계속 변경 → 변경 이력이 카톡·구두로 흩어짐.
- 근무표가 곧 근태 원본인데, 실제 근무와 근무표가 어긋나도 아무도 모름.

**B. 실근로시간을 아무도 정확히 모름**
- 인계(handover) 시간, 사전 준비 시간이 근무표에 없음 → 실제 출근은 30분 빠름.
- 당직·온콜은 대기 중 호출 여부에 따라 근로시간 인정 범위가 달라짐.
- 결과: 주 52시간 위반 여부를 사후에도 입증하기 어려움. 근로감독 시 리스크.

**C. 근태 데이터가 수가와 직결되는데 근거가 부실**
- **간호관리료 차등제(간호등급제)**: 병상 대비 간호사 수 비율로 등급이 결정되고, 등급에 따라 입원료 가산율이 달라짐. 신고 자료의 근거가 근무 기록.
- **야간전담간호사 관리료**, **야간간호료**: 야간 근무 인력 요건 충족 증빙 필요.
- 현재는 근무표 Excel과 급여대장을 사람이 대조해 신고 자료를 만듦 → 오류 시 환수 리스크.
  - ⚖️ 검토필요: 수가 산정 기준은 보건복지부 고시로 자주 변경됨. 고시 버전 관리 필수.

**D. 면허·교육 만료 관리가 안 됨**
- 의사·간호사 면허 신고(3년 주기), 보수교육 이수 평점, BLS/ACLS/KALS 인증(2년), 법정의무교육 5종, 감염관리 교육.
- 의료기관 인증평가 때 몰아서 확인 → 만료자 발견 시 대응 불가.

**E. 연차·휴가가 병원 특성과 안 맞음**
- 3교대 근무자의 연차 1일 = 몇 시간인가? (8시간? 실제 근무 시프트 길이?)
- 나이트 근무 후 오프(N-off)는 휴일인가 대체휴무인가?
- 보건휴가, 병가, 경조사휴가, 예방접종 휴가 등 병원 고유 휴가 항목이 많음.

**F. 업무 시간 중 PC 사용 통제 요구**
- 원무·행정·검사실 등 PC 상주 직군의 업무 외 사용(스트리밍, 쇼핑, 게임) 통제 요구가 실재.
- 동시에 잘못 접근하면 **근로자 감시**로 법적·노무적 분쟁이 됨.

### 1.2 왜 지금인가

- 주 52시간제·전공의법 강화로 근로시간 기록 의무의 실질적 압박이 커짐.
- 간호인력 이직률이 높아 인력 운영 효율이 경영 지표가 됨.
- LLM 등장으로 "자연어 제약 → 스케줄 최적화" 파이프라인이 실용화 가능해짐. 이전에는 제약 입력 UI를 만드는 것 자체가 불가능에 가까웠음.

## 2. 타겟 고객

### 2.1 1차 타겟 — 중소 병·의원 (직원 10~300명)
- 전문병원, 요양병원, 재활병원, 중형 검진센터, 다수 지점 네트워크 의원.
- **특징**: 전담 인사팀이 없거나 1~2명. 원장/행정실장이 의사결정. 도입 주기가 짧음(1~3개월).
- **구매 동기**: 근로감독 리스크 회피 + 근무표 작성 시간 절감 + 급여 계산 자동화.
- **가격 수용도**: 1인당 월 3,000~6,000원 수준.

### 2.2 2차 타겟 — 중대형 종합병원 (300~3,000명)
- **특징**: 인사팀·노무팀 존재. 기존 그룹웨어/ERP(더존, 영림원, 자체 시스템)와 연동 필수. 도입 주기 6~18개월, 조달·입찰.
- **구매 동기**: 전공의 수련시간 관리 + 간호등급 신고 자동화 + 인증평가 대응.
- **접근**: 1차 타겟에서 레퍼런스와 도메인 로직을 축적한 뒤 진입. 초기에 뛰어들면 커스터마이징 요구에 팀이 소진됨.

### 2.3 페르소나

| 페르소나 | 역할 | 핵심 니즈 | 성공의 정의 |
|---|---|---|---|
| 김수간 (병동 수간호사) | 듀티표 작성자 | 근무표 작성 시간 단축, 공정한 오프 배분 | 매월 3일 → 2시간 |
| 박실장 (행정실장) | 인사·급여 담당 | 급여 계산 근거, 법적 리스크 관리 | 마감 작업 반토막, 감독 대응 자료 즉시 출력 |
| 이간호 (일반 간호사) | 근무자 | 내 근무표 확인, 오프 신청, 연차 확인 | 카톡·구두 요청 → 앱에서 3탭 |
| 최원장 (경영진) | 의사결정자 | 인건비, 초과근무, 이직 리스크 가시화 | 월 1회 대시보드로 파악 |

## 3. 제품 포지셔닝

> **"병원의 근무표에서 급여·수가까지, 하나의 기록으로."**

### 3.1 경쟁 지형

| 구분 | 대표 서비스 | 강점 | 의료기관 관점의 약점 |
|---|---|---|---|
| 범용 HR SaaS | 원티드스페이스, 시프티, 플렉스, 알밤 | UX 성숙, 가격 경쟁력 | 교대·당직·전공의 로직 부재, 수가 연동 없음 |
| 대형 ERP HR | 더존, SAP SuccessFactors | 회계 통합, 대형 레퍼런스 | 비싸고 무거움, 중소 병원 부적합 |
| 병원 전용 SI | 지역 SI 업체 자체 개발 | 개별 병원에 딱 맞음 | 유지보수 종속, 확장·업데이트 부재 |
| 듀티표 전용 도구 | Excel 매크로, 일부 앱 | 무료/저가 | 근태·급여와 단절 |

**우리의 자리**: 범용 SaaS의 UX/가격 + 병원 전용 도메인 로직 + AI 스케줄링.

### 3.2 방어 가능한 해자

1. **도메인 규칙 엔진** — 근기법 특례, 전공의법, 수가 기준을 버전 관리되는 규칙으로 구현. 축적될수록 복제 난이도 상승.
2. **스케줄링 최적화 자산** — 실제 병동에서 수용된 제약 패턴 라이브러리. 데이터가 쌓일수록 초기 해가 좋아짐.
3. **수가 리포트** — 근태 → 간호등급/야간전담 신고 자료 자동 생성. 돈과 직결되어 이탈 비용이 큼.

## 5. 성공 지표

### 5.1 제품 지표

| 지표 | 목표 (출시 12개월) |
|---|---|
| 듀티표 자동 생성 채택률 | 도입 병동의 70% 이상이 AI 생성안을 기반으로 확정 |
| 듀티표 작성 소요시간 | 병동당 평균 16시간 → 2시간 이하 |
| AI 초안 수용률 | 생성된 근무표의 셀 중 85% 이상이 수정 없이 확정 |
| 출퇴근 기록 성공률 | 모바일 체크인 시도 대비 성공 99% 이상 |
| 위치 검증 오탐률 | 정상 출근인데 거부되는 비율 0.5% 이하 |

### 5.2 사업 지표

| 지표 | 목표 |
|---|---|
| 유료 기관 수 | 12개월 내 50개 기관 |
| 기관당 평균 인원 | 80명 |
| 월 이탈률(기관 기준) | 1.5% 이하 |
| 도입 리드타임 | 계약 → 전사 사용까지 4주 이내 |

### 5.3 반드시 함께 볼 역지표
- **관리자 수동 개입 비율** — AI 생성 후 관리자가 손댄 셀 비율이 높으면 최적화 모델이 현실을 반영 못 하는 것.
- **PC 통제 기능 관련 직원 이의제기 건수** — 이 수치가 오르면 제품이 노무 리스크를 만들고 있다는 신호.
- **위치 검증 실패 재시도 후 수동 승인 비율** — 높으면 지오펜스 설정이 병원 구조와 안 맞는 것.

## 6. 명시적 비목표 (Non-Goals)

초기에 하지 **않을** 것을 정의해야 범위가 지켜집니다.

| 비목표 | 이유 |
|---|---|
| 급여 계산·이체 직접 수행 | 4대보험·원천징수는 규제와 검증 부담이 큼. **급여 원천 데이터 산출 + 급여 시스템 연동(Export/API)** 까지만. |
| EMR/OCS 통합 | 환자 정보가 들어오면 규제 등급이 완전히 달라짐. 근태·인사 도메인에 머무름. |
| 채용(ATS) | 별개 제품. 후순위. |
| 직원 PC 화면 캡처·키로깅 | 법적 리스크 대비 효용이 낮고, 제품 신뢰를 파괴함. **영구 비목표.** |
| 개인 위치의 상시 추적 | 출퇴근 판정 시점의 검증만. 상시 위치 이력은 수집하지 않음. **영구 비목표.** |

마지막 두 항목은 단순한 우선순위가 아니라 **제품 원칙**입니다. 상세는 [09. PC 사용 통제](09-pc-usage-control.md), [10. 보안·규제 준수](10-security-compliance.md) 참고.
