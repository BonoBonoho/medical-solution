# 01. 기능 요구사항

우선순위는 MoSCoW로 표기합니다.
`M` Must (MVP 필수) · `S` Should (MVP 직후) · `C` Could (여유 시) · `W` Won't (이번 범위 제외)

## K. 비기능 요구사항

### K-1. 성능
- 근무표 그리드: 200명 × 31일 렌더링 및 편집 반응 < 100ms.
- 출퇴근 기록 API: p95 < 300ms (위치 검증 포함).
- AI 근무표 생성: 50명 규모 병동 1개월 → 60초 이내에 실행 가능한 해 제시. (최적해가 아니어도 됨. 좋은 해를 빨리.)
- 월 근태 마감 집계: 1,000명 기관 → 5분 이내.

### K-2. 가용성
- 목표 가용성 99.9%.
- **출퇴근 기록은 서버 장애 시에도 유실되면 안 됨** — 모바일 로컬 큐 + 재시도. 사용자에게 "기록됨"을 표시하는 시점은 서버 확정 후.

### K-3. 보안
- 전송 TLS 1.3, 저장 암호화(AES-256). 주민등록번호 등 고유식별정보는 컬럼 단위 암호화 + 별도 키 관리.
- 개인정보 조회 이력 기록.
- 상세는 [10. 보안·규제 준수](10-security-compliance.md).

### K-4. 접근성·사용성
- 모바일 출퇴근은 **앱 실행 후 2탭 이내**. 교대 시간에 수십 명이 동시에 쓰는 화면.
- 웹은 WCAG 2.1 AA 지향. 연령대가 넓은 행정직 사용을 고려해 최소 글자 크기 14px, 명확한 대비.
- 다크모드 지원(야간 근무자).

### K-5. 확장성
- 멀티테넌시. 단일 기관 최대 5,000명까지 성능 저하 없이 지원.
- 근무유형·휴가종류·결재선은 코드 수정 없이 기관이 설정 가능해야 함. **하드코딩된 근무유형은 즉시 기술 부채가 됨.**

### K-6. 감사 추적
- 근태 기록·근무표·휴가 잔액의 모든 변경은 who/when/what/why를 남김.
- 원본 기록은 **절대 덮어쓰지 않음**. 수정은 새로운 레코드 + 참조.
