# 07. 휴가 관리

> ⚖️ 이 문서의 연차 산정 로직은 근로기준법 해석에 기반합니다. 실제 구현 전 **공인노무사 검증**이 필요하며, 특히 회계연도 기준 운영, 사용촉진 절차, 3교대 근무자의 일수 환산은 다툼의 소지가 있는 영역입니다.

---

## 1. 연차유급휴가 산정

### 1.1 부여 규칙

| 조건 | 부여 일수 | 근거(확인 필요) |
|---|---|---|
| 계속근로 1년 미만 | 1개월 개근 시 1일 (최대 11일) | 근기법 §60② |
| 1년간 80% 이상 출근 | 15일 | 근기법 §60① |
| 1년간 80% 미만 출근 | 1개월 개근 시 1일 | 근기법 §60② |
| 계속근로 3년 이상 | 15일 + 최초 1년 초과 매 2년당 1일 가산 (총 25일 한도) | 근기법 §60④ |

**가산연차 계산**

```
근속연수 n (년)에 대해:
  n < 1   → 월 단위 부여
  1 ≤ n < 3 → 15일
  n ≥ 3   → 15 + floor((n - 1) / 2)  일, 최대 25일

검산: n=3 → 15 + floor(2/2) = 16일
      n=5 → 15 + floor(4/2) = 17일
      n=21 → 15 + floor(20/2) = 25일 (한도 도달)
      n=23 → 15 + 11 = 26 → 25일로 제한
```

### 1.2 입사일 기준 vs 회계연도 기준

| 기준 | 장점 | 단점 |
|---|---|---|
| **입사일 기준** | 법적으로 가장 명확 | 직원마다 발생일이 달라 관리 복잡 |
| **회계연도 기준** | 전사 일괄 관리 가능 | 입사 첫 해 비례 부여 필요, 퇴직 시 정산 필요 |

- 실무에서는 회계연도 기준이 널리 쓰이지만, **퇴직 시점에 입사일 기준으로 계산한 값보다 적으면 안 됩니다.**
- 따라서 시스템은 **두 방식을 병행 계산**하고, 퇴직 정산 시 유리한 쪽을 적용하는 검증 기능을 제공해야 합니다.

```typescript
interface AnnualLeaveCalculation {
  method: 'HIRE_DATE' | 'FISCAL_YEAR';
  grants: LeaveGrant[];
  // 회계연도 기준일 때, 입사일 기준 대비 부족분 검증
  hireDateComparison?: {
    hireDateBasisDays: number;
    fiscalBasisDays: number;
    shortfall: number;        // > 0 이면 추가 부여 필요
  };
}
```

**이 비교 기능이 실무 가치가 큽니다.** 대부분의 병원이 회계연도 기준으로 운영하면서 이 검증을 안 하고 있고, 퇴직 정산 분쟁의 흔한 원인입니다.

### 1.3 출근율 산정

80% 출근율 계산 시 **출근으로 간주하는 기간**이 있습니다.

| 기간 | 처리 |
|---|---|
| 업무상 부상·질병 휴업 | 출근으로 간주 |
| 출산전후휴가 | 출근으로 간주 |
| 육아휴직 | 출근으로 간주 |
| 연차 사용일 | 출근으로 간주 |
| 개인 사유 휴직 | 소정근로일수에서 제외 후 비례 계산 (해석상 논점 있음) |
| 무단결근 | 결근 |

⚖️ 검토필요: 개인 사유 휴직 기간의 처리는 판례·행정해석에 따라 달라집니다.

```sql
-- 산정 근거를 반드시 저장 (leave_grant.grant_basis)
{
  "period": {"from": "2025-01-01", "to": "2025-12-31"},
  "prescribedWorkDays": 248,
  "attendedDays": 231,
  "deemedAttendedDays": 12,     -- 출산휴가 등
  "excludedDays": 0,
  "absentDays": 5,
  "attendanceRate": 0.9798,
  "ruleSetVersion": "kr-annual-2026.1"
}
```

나중에 "왜 이만큼 받았나"를 물었을 때 답할 수 있어야 합니다.

## 2. 부여 원장(Grant Ledger) 방식

[04. 데이터 모델 §6](04-data-model.md#6-휴가)에서 설명한 대로, 잔액을 단일 숫자로 두지 않고 **부여 건별 원장**으로 관리합니다.

### 2.1 차감 알고리즘 — 선입선출 + 소멸임박 우선

```typescript
function deduct(grants: LeaveGrant[], requiredDays: number, useDate: Date) {
  const available = grants
    .filter(g => g.effectiveFrom <= useDate && g.expiresAt >= useDate)
    .filter(g => g.remaining > 0)
    .sort((a, b) => a.expiresAt - b.expiresAt);   // 먼저 소멸하는 것부터

  let remain = requiredDays;
  const deductions = [];
  for (const g of available) {
    if (remain <= 0) break;
    const take = Math.min(g.remaining, remain);
    deductions.push({ grantId: g.id, days: take });
    remain -= take;
  }
  if (remain > 0) throw new InsufficientBalanceError(remain);
  return deductions;
}
```

**소멸임박 우선 차감이 직원에게 유리합니다.** 나중에 소멸할 연차를 먼저 쓰면 임박한 연차가 그냥 소멸해버립니다.

### 2.2 취소 시 복원

휴가를 취소하면 **차감했던 grant에 정확히 되돌려야** 합니다. 이미 소멸한 grant로 복원되는 경우 처리 정책이 필요합니다.

```
취소 시점에 원래 grant가 이미 소멸했다면?
  옵션 A: 소멸 처리 (직원 불리)
  옵션 B: 현재 유효한 grant로 이월 (직원 유리, 기관 정책)
→ 기관 설정으로 선택. 기본값은 B.
```

## 3. 휴가 종류

### 3.1 기본 제공 목록

| 코드 | 명칭 | 유급 | 잔액차감 | 단위 | 비고 |
|---|---|---|---|---|---|
| `ANNUAL` | 연차 | ○ | ANNUAL | 일 | |
| `ANNUAL_HALF` | 반차 | ○ | ANNUAL(0.5) | 반일 | 오전/오후 |
| `ANNUAL_QUARTER` | 반반차 | ○ | ANNUAL(0.25) | 2시간 | 기관 선택 |
| `COMP` | 보상휴가(대체휴무) | ○ | COMP_LEAVE | 일 | 서면합의 필요 ⚖️ |
| `MENSTRUAL` | 보건휴가 | 정책 | ✕ | 일 | 월 1일, 무급이 일반적 ⚖️ |
| `SICK` | 병가 | 정책 | ✕ | 일 | 기관 규정 |
| `MATERNITY` | 출산전후휴가 | 법정 | ✕ | 일 | 90일(다태아 120일) ⚖️ |
| `SPOUSE_BIRTH` | 배우자 출산휴가 | 법정 | ✕ | 일 | ⚖️ 일수 확인 필요 |
| `FAMILY_CARE` | 가족돌봄휴가 | 무급 | ✕ | 일 | ⚖️ |
| `CONDOLENCE` | 경조사휴가 | ○ | ✕ | 일 | 기관 규정, 사유별 일수 |
| `OFFICIAL` | 공가 | ○ | ✕ | 일 | 예비군, 건강검진 등 |
| `VACCINATION` | 예방접종 | ○ | ✕ | 시간 | 병원 고유 |
| `UNPAID` | 무급휴가 | ✕ | ✕ | 일 | |

⚖️ 법정휴가의 일수·유급 여부는 개정이 있으므로 **현행 조문 확인 후 기본값을 설정**해야 합니다. 기관이 값을 조정할 수 있게 해두면 개정 대응이 쉬워집니다.

### 3.2 기관 커스텀

병원마다 고유 휴가가 있습니다 (예: 근속 포상휴가, 학회 참석). `leave_type`을 테넌트별로 추가할 수 있어야 하고, **코드 배포 없이 관리자 화면에서** 만들 수 있어야 합니다.

## 4. ⭐ 3교대 근무자의 연차 처리

이 부분이 범용 HR SaaS가 가장 크게 틀리는 지점입니다.

### 4.1 문제

```
간호사 A: 12시간 2교대 근무 (07:00~19:00)
  → 연차 1일을 쓰면 12시간을 쉰다
  → 잔액에서 1일을 빼는 게 맞나? 1.5일인가?

간호사 B: 8시간 3교대
  → 연차 1일 = 8시간. 자명.
```

### 4.2 정책 옵션

```typescript
type LeaveDayEquivalence =
  | 'FIXED_8H'          // 연차 1일 = 8시간. 12h 시프트 → 1.5일 차감
  | 'SHIFT_LENGTH'      // 연차 1일 = 해당 시프트 길이. 12h → 1일 차감
  | 'CONTRACTUAL_DAILY' // 연차 1일 = 근로계약상 1일 소정근로시간
```

| 정책 | 12h 시프트에 연차 사용 시 | 유불리 |
|---|---|---|
| `FIXED_8H` | 1.5일 차감 | 기관 유리 |
| `SHIFT_LENGTH` | 1.0일 차감 | 직원 유리 |
| `CONTRACTUAL_DAILY` | 계약에 따름 | 중립 |

⚖️ **검토필요**: 근로자에게 불리한 방식은 취업규칙 불이익 변경 절차가 필요할 수 있습니다. 기본값은 `SHIFT_LENGTH`(직원 유리)로 두고, 변경 시 경고를 표시합니다.

### 4.3 나이트 오프(N-off)의 성격

```
나이트 근무: 7/29 22:00 ~ 7/30 08:00
7/30은 무엇인가?
  - 근무일인가? (7/30 08:00까지 일했으므로)
  - 휴무일인가? (7/30에 추가 근무가 없으므로)
```

**시스템 처리**: 야간근무는 **시작일 기준**으로 `work_date`를 기록합니다 (위 예에서 7/29). 7/30은 근무 배정이 없는 날(`O`)이 됩니다.

다만 이건 집계 기준일 뿐이고, **주휴일 판정과는 별개**입니다. N 근무 다음날을 주휴일로 볼지 단순 휴무로 볼지는 기관 정책이며, 주휴수당 지급 여부가 달라집니다. ⚖️

## 5. 결재 흐름

### 5.1 범용 결재 엔진 사용

휴가·야근·근태수정·근무교환·PC차단해제가 모두 같은 엔진을 씁니다. ([03. 아키텍처 §4.1](03-architecture.md#41-모듈-간-규칙))

```jsonc
// approval_flow.steps
[
  { "order": 1, "approverType": "DIRECT_MANAGER" },
  { "order": 2, "approverType": "DEPT_HEAD",
    "condition": { "daysCount": { "gte": 3 } } },      // 3일 이상만 부서장 결재
  { "order": 3, "approverType": "ROLE", "roleCode": "HR_MANAGER",
    "condition": { "leaveTypeCode": { "in": ["MATERNITY","UNPAID"] } } }
]
```

### 5.2 병원 특유의 요구

| 요구 | 처리 |
|---|---|
| 수간호사 부재 시 대결 | `delegated_from` 기록. 위임 기간 설정. |
| 야간 근무자가 낮에 결재 못 받음 | 모바일 푸시 + 알림톡. 결재 지연 알림. |
| 병동 인력 부족 시 자동 경고 | 신청 시 `warnings`에 coverage 영향 포함 |
| 동시 휴가 인원 제한 | `leave_type` 또는 부서 단위로 상한 설정 |

### 5.3 승인자 화면의 필수 정보

```
┌─────────────────────────────────────────────┐
│ 휴가 신청 · 김간호 (3병동 간호사)             │
│ ─────────────────────────────────────────── │
│ 연차  8/12(수) ~ 8/13(목)  2일               │
│ 사유: 가족 여행                              │
│                                             │
│ ⚠️ 영향 분석                                 │
│   8/12 데이 근무 인원 5명 → 4명 (최소 5명)    │
│   같은 기간 휴가자: 이간호(8/12)              │
│                                             │
│ 잔액: 8.5일 → 6.5일                          │
│ 소멸임박: 3일 (12/31 소멸)                    │
│                                             │
│  [ 승인 ]  [ 반려 ]  [ 보류 ]                │
└─────────────────────────────────────────────┘
```

**영향 분석 없이 승인 버튼만 보여주면 안 됩니다.** 수간호사가 근무표를 따로 열어보고 판단해야 한다면 결재 기능의 가치가 절반입니다.

## 6. 연차 사용촉진

근기법 §61 절차를 시스템으로 진행하고 증빙을 남깁니다.

### 6.1 절차 (개요)

```
① 1차 촉구  : 사용자가 근로자에게 미사용 연차 일수를 알리고
              사용 시기 지정·통보를 촉구
② 근로자 통보: 근로자가 사용 시기를 정해 통보
③ 사용자 지정: 근로자가 통보하지 않으면 사용자가 시기를 지정해 통보
```

⚖️ **검토필요**: 각 단계의 시기(연차 사용기간 만료 전 며칠), 서면 요건, 1년 미만 근로자에 대한 별도 절차는 조문을 직접 확인해야 합니다. **절차를 지키지 못하면 미사용 수당 지급 의무가 남으므로 시기 계산이 정확해야 합니다.**

### 6.2 시스템 지원

```
┌──────────────────────────────────────────────┐
│ 2026년 연차 사용촉진                          │
│ ──────────────────────────────────────────── │
│ 대상자 34명 · 미사용 연차 총 187일             │
│                                              │
│ ● 1단계 촉구      완료 (2026-07-01, 34명)     │
│ ● 근로자 통보      진행중 (18/34 응답)         │
│ ○ 2단계 시기지정   예정 (2026-10-15)          │
│                                              │
│ [ 미응답자에게 재알림 ]  [ 증빙 다운로드 ]     │
└──────────────────────────────────────────────┘
```

- 각 단계의 통보 사실·일시·방법을 `leave_promotion`에 기록하고 **PDF 증빙을 생성**합니다.
- 근로감독이나 분쟁 시 이 기록이 그대로 증거가 됩니다. 이게 이 기능의 핵심 가치입니다.
- 시스템 알림만으로 서면 요건을 충족하는지는 ⚖️ 검토 대상입니다. 필요시 문서 출력 + 서명 수령 흐름을 병행합니다.

## 7. 보상휴가(대체휴무)

### 7.1 발생

연장·야간·휴일근로에 대해 수당 대신 휴가를 부여하는 제도(근기법 §57). **근로자대표와의 서면합의가 필요합니다.** ⚖️

```
보상휴가 시간 = 가산율이 반영된 시간
  예) 휴일근로 8시간 (가산 50%) → 8 × 1.5 = 12시간의 보상휴가
```

가산율을 반영하지 않고 1:1로 부여하면 법 위반 소지가 있습니다. **시스템이 자동 계산해야 하는 부분**입니다.

### 7.2 관리

```sql
-- leave_grant에 balance_source = 'COMP_LEAVE' 로 적재
{
  "grant_reason": "COMPENSATORY",
  "granted_days": 1.5,
  "grant_basis": {
    "sourceWorkDate": "2026-07-20",
    "sourceType": "HOLIDAY_WORK",
    "actualMinutes": 480,
    "premiumRate": 1.5,
    "compensatedMinutes": 720
  },
  "expires_at": "2026-12-31"    -- 합의서에 정한 기간
}
```

- 보상휴가는 **소멸 시 수당으로 정산**해야 하는 것이 일반적입니다. 소멸 예정 알림이 필수입니다. ⚖️

## 8. 휴직 관리

| 휴직 유형 | 연차 산정 영향 | 4대보험 | 근무표 |
|---|---|---|---|
| 육아휴직 | 출근으로 간주 | 납부예외 등 | 배정 제외 |
| 산재휴업 | 출근으로 간주 | — | 배정 제외 |
| 병휴직 (개인) | ⚖️ 해석 논점 | — | 배정 제외 |
| 무급휴직 | ⚖️ 해석 논점 | — | 배정 제외 |

**휴직자는 근무표 배정 대상에서 자동 제외**되어야 하고, AI 스케줄러의 입력에서도 빠져야 합니다. 이걸 놓치면 휴직자가 근무표에 배정되는 사고가 납니다.

또한 **간호등급 산정 시 휴직자 제외 처리**와 연결됩니다. ([02. 도메인 규칙 §6.1](02-domain-rules.md#61-간호관리료-차등제-간호등급제))

## 10. 계산 검증 전략

연차 계산 버그는 **급여 오지급으로 직결**되므로 테스트가 가장 두꺼워야 하는 영역입니다.

### 10.1 반드시 커버할 케이스

```
□ 입사 1개월 미만 (부여 0)
□ 입사 후 매월 개근 → 11개월까지 월 1일
□ 만 1년 도달 시점의 15일 부여와 월차 11일의 관계
□ 1년 미만 기간의 80% 미만 출근
□ 3년차 경계 (15일 → 16일)
□ 25일 한도 도달 후 (21년차 이상)
□ 회계연도 기준 첫 해 비례 부여
□ 회계연도 기준 vs 입사일 기준 퇴직 정산 비교
□ 육아휴직 기간 포함 출근율 계산
□ 반차·반반차 혼합 사용 시 소수점 누적 오차
□ 소멸임박 우선 차감 순서
□ 휴가 취소 시 소멸된 grant로의 복원
□ 12시간 교대 근무자의 일수 환산 (3가지 정책 각각)
□ 윤년 (2/29 근무일 계산)
□ 입사일이 2/29인 직원의 근속연수 계산
```

### 10.2 소수점 처리

```
❌ float 사용 → 0.1 + 0.2 !== 0.3 문제로 잔액이 8.499999999 가 됨
✅ numeric(5,2) + 계산은 정수 기반 (0.25일 = 25 단위) 후 변환
```

반차·반반차를 쓰면 0.25 단위 누적이 반복됩니다. 부동소수점을 쓰면 반드시 문제가 생깁니다.
